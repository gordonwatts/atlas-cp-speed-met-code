# M27 jet track-count offset validation

The production diff changes only the lifetime of the checked `jet.ntrk.o`
view. The full event entry owns one optional view per chunk. It performs the
original first access from `prepare_views`, after the flat `jet.ntrk` lookup
and before preparing objects. An empty chunk never binds the fields. Each
jet still goes through the existing row and flat-length checks when reached,
including rows with duplicated offsets. Jet sampling uses the original path.

Build the normal immutable trial as before. The default library has no counters
or fixture symbols. Build a separate untimed receipt with the same source and
toolchain settings, adding only `-DATLAS_MET_M27_DIAGNOSTICS=ON`. For example,
from a fresh pinned release build shell after setting `snapshot` to the normal
immutable M27 archive and `diagnostic` to a new result directory:

```bash
repo=$PWD
sdk="$repo/vendor/correctionlib-exact-001"
core="$repo/results/core-exact-build-001/install/correctionlib"
lwtnn="$repo/results/core-exact-build-001/build/lwtnn/lib/liblwtnn-stat.a"
jvt=/home/gwatts/atlas-cp-speed/jets-skill-c8a2374-20261117/provider
source="$snapshot/source/components/columnar"
runtime="$diagnostic/runtime"
mkdir -- "$diagnostic"
taskset -c 0 cmake -S "$source" -B "$diagnostic/build" \
    -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_STANDARD=23 -DCMAKE_CXX_STANDARD_REQUIRED=ON \
    -Dcorrectionlib_DIR="$core/cmake" -DATLAS_MET_PINNED_SDK="$sdk" \
    -DATLAS_MET_LWTNN="$lwtnn" -DATLAS_MET_SMALL_JVT="$jvt" \
    -DATLAS_MET_COLUMNAR_PREPARATION=ON -DATLAS_MET_M27_DIAGNOSTICS=ON
taskset -c 0 cmake --build "$diagnostic/build" --parallel 1
cmake --install "$diagnostic/build" --prefix "$runtime"
cp "$snapshot/runtime/native"/lib{correctionlib.so,stdc++.so.6,gcc_s.so.1} "$runtime/native/"
cp -a "$snapshot/runtime/payloads" "$runtime/payloads"
env LD_LIBRARY_PATH="$runtime/native" taskset -c 0 \
    "$python314" "$source/check_ntrk_offsets.py" "$runtime/native/libatlas_met_columnar.so"
env LD_LIBRARY_PATH="$runtime/native" taskset -c 0 \
    "$python314" "$source/met_demo.py" "$input" "$diagnostic/c.npz" \
    --runtime "$runtime" --stop 16 --chunk-size 7 --trace "$diagnostic/trace.tsv"
env LD_LIBRARY_PATH="$runtime/native" taskset -c 0 \
    "$python314" "$source/check_ntrk_offsets.py" "$runtime/native/libatlas_met_columnar.so" \
    --trace "$diagnostic/trace.tsv" --entries 16 --chunk-size 7
```

The fixture exercises empty and nonempty chunks, missing field precedence,
duplicate and decreasing offsets, and an out-of-range row following a valid
row. The diagnostic trace writes one row at the end of each completed chunk
with its starting entry, size and observed constructor call count. The prefix
above expects three calls for chunks of seven, seven and two entries. The
existing trace comparator can ignore this diagnostic action while validating
all physics rows. Keep the diagnostic library out of production timing and
distribution. Use the unchanged full tuple and physics comparisons before
timing the normal trial artifact.
