# M03 first soft Gaussian trial

This is a source-only trial based on the faithful C implementation in
`6b19c477e8d5578bb2c8c3a5e0eccc11e3437759`. The C caller creates one cache for
each input event. The cache holds the first Gaussian for one nonzero effective
seed. A different seed replaces the slot. The draw uses the existing
`root_rng::first_gaussian` on every miss. Seed derivation, recorded setter arguments, table lookups, calculation order,
and logical draws stay per state. Nominal and any
earlier-returning status skip the cache. The stock framework entry point
`SoftFile::apply` and the layout of its result stay unchanged.

Each state has the stock reseed semantics. `first_gaussian` creates a local MT19937, extracts the first
Gaussian and discards the engine. AnalysisBase 25.2.117
`MetAnalysisAlgorithms/Root/MetMakerAlg.cxx:199-204` reseeds before every
correction. `METUtilities/Root/METSystematicsTool.cxx:387-425` takes one
Gaussian after the shift lookup, and lines 808-811 replace a zero setter
argument by one. `METSystematicsTool.h:134-167` places the thread-local
generator in the private implementation. The existing portable soft result
contains the first value and decision diagnostics. Neither that result nor the soft interface
exposes later words or owns an engine. Scale-up and scale-down retain a
logical draw even though their output does not consume the sampled value.

The new optional `firstGaussian` trace shows the seed and physical evaluation,
reuse, or skip. Existing `gaussian` rows still carry the exact stock logical
draws. The check uses the independent stock setter, ROOT seed, and Gaussian
trace to derive expected dispositions. The first physical evaluation belongs
to whichever active state occurs first. For the frozen input, expect
80,000 logical draws, 20,000 physical evaluations, and 60,000 hits in production.
The separate two-state correlated diagnostic expects 20,000 logical and physical
draws, with no hits. Nominal alone expects no logical or physical draw.

Apply the patch only to an isolated accepted source worktree. Use a fresh
immutable C build and results directory. Build the existing soft smoke target
against that snapshot and run it with the accepted soft payload:

```bash
cmake --build "$snapshot/build" --target met_soft_smoke --parallel 1
env LD_LIBRARY_PATH="$snapshot/runtime/native" taskset -c 0 \
    "$snapshot/build/soft/met_soft_smoke" "$snapshot/runtime/payloads/soft.json"
```

On a first 16-event run and then the full 20,000-event run, capture the existing
C `--trace` and `--observables` and run the normal complete A/C comparison for
each workload. Check actual RNG evaluations with the corresponding A trace:

```bash
"$python314" "$snapshot/source/components/columnar/check_first_gaussian_trace.py" \
    "$stock_status" "$candidate_status" "$output_json" --entries 20000
```

For the early smoke set `--entries 16`. A nominal-only trace can use the
production A status file with `--nominal-only`, which takes only its nominal RNG
rows. The synthetic soft smoke covers exact momentum and intermediate stages
for ordered and reordered switches, seed mismatch, effective-one fallback,
guard cutoffs, and independent event cache lifetimes. If numerical acceptance
passes, package and time the C candidate independently using a fresh wheel and
the matched C-only timing harness. Keep the accepted prior C bundle available
as the fallback.
