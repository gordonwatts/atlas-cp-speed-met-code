# Fixed PFlow Tight MET maker

The component implements the AnalysisBase 25.2.117 maker for PFlow Tight jets with NNJVT, muon-jet removal and EM-scale handling, and the track soft term. It returns the maker terms before the soft variation, Final sum and significance. The campaign provider controls those calls and supplies the same nominal objects to each MET state.

## Provider interface

Link the CMake target `atlas::met_maker`. Include `met_maker/maker.hpp` and call `atlas::met::maker::evaluate(config, event)` from the registered CorrectionLib event operation. The static target uses C++20 and the standard library. It has no runtime dependency on xAOD, ROOT or the release cut file. Treat `Config` as immutable after provider initialization. `EventInput` and every span it refers to must stay alive through the call. Returned records own their data and every call starts with zero association flags.

- Set the four hard-object views in the actual in-container order after the initialized upstream selections. Supply the full jet view in its order. Carry current rows and each resolvable original or association-linked row under a canonical owner/index key. Include linked muons, electrons, reference jets and other valid link targets even when absent from selected views.
- Resolve link keys to the actual event-local owning objects before building `ObjectId`. Keep different owning collections distinct and collapse StoreGate aliases only when they resolve to the same owner. Keep raw link null and unresolved states distinguishable. Do not drop or renumber either kind of association slot. Flag original-link decoration availability separately from link validity. A view's first selected object determines whether the reference uses original links for that view.
- Preserve the input order of associations, overlap edges, keyed vectors and core rows. Each `overlap_rows` entry corresponds to one `objectLinks` slot, even for an empty row. Supply float components and uint64 masks directly from the map. Keep the full original vertex-type sequence for per-PV jet moments.
- Use current p4 values obtained independently from the original file and the configured nominal upstream tools. The JVT input is the initialized selector's `JetEtaName` float decoration and `NNJvt` score. The selector's default `JetEtaName` is `eta`. Expose the chosen constituent-scale p4 and the jet per-vertex moment arrays as distinct inputs. For the original associated muon, supply `EnergyLoss`, `energyLossType`, `muonType` and ID-track pT where the track link resolves.
- Materialize the seven maker terms in returned order. Each constituent refers to the current object's owning collection and row. For hard terms, materialize weights including the intentional zero missing-electron weight. For `PVSoftTrk`, only materialize its jet links, with an empty weight vector wherever the xAOD auxiliary store has created the weight decoration. `MuonEloss` carries a vector and has no contributors. The two availability flags indicate whether the corresponding vectors exist in the xAOD output store. Significance consumes the ordered hard links and the TST term vector.
- Handle `Status::failure` as a stock failure. `source_access_exception` preserves a missing required field, failed dereference, or unbound valid target in the adapter contract. Detailed diagnostics identify the affected term and object where available. `stock_undefined` classifies executed release expressions for which C++ does not define a result. It includes out-of-range legacy signed mask shifts and unchecked moment indices. Partial records describe the failure and should not be recorded as successful events. `unsupported_input` covers a core with the wrong source for this fixed track recipe.

The fixed recipe requires the standard CP term keys, electron-photon-tau-muon order, `DoPFlow=true`, active JVT, the default `JetConstitScaleMomentum` constituent p4, `DoRemoveMuonJets=true`, `DoSetMuonJetEMScale=true`, `DoRemoveElecTrks=true` and `ORCaloTaggedMuons=true`. The campaign configuration keeps truth and calo soft modes, invisible objects, fJVT, optional soft-constituent export, greedy photons, ghost muons, `DoMuonEloss`, phi correction and nominal-link replacement inactive. The provider should check these prerequisites against the initialized job before selecting this recipe.

## NNJVT configuration payload

Resolve the initialized selector's `ConfigDir` and `ConfigFile` with the release `PathResolver`. `NNJvtSelectionTool` uses `JetPileupTag/NNJvt/2022-03-22/NNJVT.Cuts.FixedEffPt.Offline.Nonprompt_All_MaxW.json` when the configuration file uses the default for FixedEffPt. The file under the CVMFS GroupData directory was inspected with SHA-256 `a29154427f1da0c33095a587fcb2d110e63203713d0f39a4bc54a71f680f2e56`. Verify the actual resolved file for the run.

Run `python components/maker/export_nnjvt.py RESOLVED_CUTS_JSON NEW_EXPORT_JSON` during payload generation. The exporter records the source checksum and lowers the release arrays to `pt_edges_mev`, `eta_edges` and row-major `cuts`. It rounds JSON numbers to float32 before multiplying pT edges by 1000 and rounds the multiplication again. The provider loads the exported arrays as floats and constructs `Config(NnjvtCutMap, JvtRange)` from them and the initialized JVT bounds. The release selection uses pT and absolute eta for its range guard, signed eta for the cut, right-closed intervals, a low-pT fold, and `-1` outside the cut table. Within range the score comparison is strict. Missing score inputs are evaluated only when the release evaluates the score.

## Focused checks

`ATLAS_MET_MAKER_BUILD_TESTS=ON` registers the `atlas_met_maker_cases` CTest. The cases cover current and original ownership, zero-weight electron membership, PFlow and CaloTagged-muon overlap, legacy signed masks, NNJVT cut boundaries, alternate constituent vectors, JVT rejection into TST, muon removal and EM-scale FSR, presampler fallback, a missing core and first/last miscellaneous association handling. Synthetic cut values are confined to the test. The runtime owner should run these and the independent real-file comparisons. This component has undergone source inspection only.
