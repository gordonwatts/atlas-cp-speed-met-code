# Framework replacement for AnalysisBase 25.2.117

In the frozen CPRun configuration, the bridge replaces the execute methods of `seq1_MetMakerAlg_AnaMET`, `seq1_MetBuilderAlg_AnaMET` and `seq1_MetSignificanceAlg_AnaMET`. AnalysisBase still initializes the named tools and provides the nominal upstream object preparation, selections and systematics list. The maker bridge marshals the original association and core rows and the actual selected and owned xAOD objects. It writes the shared maker calculation's ordered terms and links through the original output handle. The full bridge uses the shared soft, Final and significance nodes after the corresponding input-handle reads. The significance adapter carries the compiled node's tool-equivalent state across the release event and systematic sequence.

The `maker_only` stage deliberately uses the original soft, Final and significance operations after the shared maker. It is a diagnostic dispatch check. The `full` stage requires every shared operation and the matching compiled bridge and payloads. Neither stage runs on other configured algorithm instance names.

## Build and smoke

Use a fresh results directory, the same compiler as the installed CorrectionLib core and the pinned AnalysisBase release. The following assumes the runtime owner's fresh `core-build-001` install. Substitute the actual pinned install if it differs.

```bash
cd /home/gwatts/atlas-cp-speed/met-20261119
source scripts/release_environment.sh
core_dir="$PWD/results/core-build-001/install/correctionlib/cmake"
release_config="$AtlasArea/InstallArea/$CMTCONFIG/cmake"
stage_build="$PWD/results/framework-build-maker-check-001"
taskset -c 0 cmake -S components/framework -B "$stage_build" \
    -Dcorrectionlib_DIR="$core_dir" -DAnalysisBase_DIR="$release_config" \
    -DATLAS_MET_ADAPTER_BUILD_SMOKE=ON
taskset -c 0 cmake --build "$stage_build" -j1

export ATLAS_MET_PROVIDER="$stage_build/maker_adapter/libatlas_met_maker_provider.so"
export ATLAS_MET_MAKER_PAYLOAD="$PWD/results/framework-payload-check-001/maker.json"
export ATLAS_MET_STAGE=maker_only ATLAS_MET_DISPATCH_AUDIT=1
taskset -c 0 bash components/framework/run.sh "$stage_build/libAtlasMetFramework.so" \
    "$PWD/results/framework-maker-smoke-001" full_systematics 16 > "$stage_build/maker-smoke.log" 2>&1
python components/framework/verify_dispatch.py results/framework-maker-smoke-001 \
    "$stage_build/maker-smoke.log" --expected-calls 80
```

Prepare the maker JSON first as described in [maker_adapter](../maker_adapter/README.md). For a separate full bridge build, use a new build directory and `-DATLAS_MET_FULL_BRIDGE=ON`. Set `ATLAS_MET_STAGE=full` and use that build's common provider. Also set `ATLAS_MET_SOFT_PAYLOAD` to the absolute soft `corrections.json` exported from the frozen initialization and set `ATLAS_MET_SIGNIFICANCE_PAYLOAD` to the absolute event significance JSON generated by the shared adapter exporter. The dispatch audit for a full 16-entry, five-state smoke should report 80 calls each to maker, soft, Final and significance. The full acceptance and timing runs must use the campaign's matched outputs and stock comparators.

The Python bootstrap loads the bridge with `ctypes.CDLL(..., RTLD_GLOBAL)` before importing ROOT or executing the release CPRun script. An optionally supplied absolute `ATLAS_MET_FRAMEWORK_OBSERVER` loads the selected observer immediately after the bridge. The child environment excludes inherited loader overrides. This preserves the same process and configuration without propagating the interposer to ROOT helper processes. When `ATLAS_MET_DISPATCH_AUDIT=1`, the bootstrap resolves live symbol owners with `dladdr` and writes `binding-map.json`. The bridge separately records the operations it actually ran. Keep both proofs for the smoke and disable this audit for matched production timing.

The stock exported symbols for AnalysisBase 25.2.117 were checked directly with `nm -D`. Use the following sources for the retained framework lifecycle and handle contracts. [MetMakerAlg](https://gitlab.cern.ch/atlas/athena/-/blob/6ce3f7ae7c41dd9eaec170c3c349df15faef7e5c/PhysicsAnalysis/Algorithms/MetAnalysisAlgorithms/Root/MetMakerAlg.cxx) / [MetBuilderAlg](https://gitlab.cern.ch/atlas/athena/-/blob/6ce3f7ae7c41dd9eaec170c3c349df15faef7e5c/PhysicsAnalysis/Algorithms/MetAnalysisAlgorithms/Root/MetBuilderAlg.cxx) / [MetSignificanceAlg](https://gitlab.cern.ch/atlas/athena/-/blob/6ce3f7ae7c41dd9eaec170c3c349df15faef7e5c/PhysicsAnalysis/Algorithms/MetAnalysisAlgorithms/Root/MetSignificanceAlg.cxx).

For ordered maker acceptance, set absolute new path `ATLAS_MET_MAKER_TRACE_FILE` in a dedicated B diagnostic run. The trace includes stock-shaped associationFlag and jetJvt rows plus the original owner/index and term in associationActor records. Compare ordered rows by entry, state and action with the independent stock trace. Compare histogram and candidate output from otherwise identical traced and untraced B runs to check that instrumentation is observational. Leave the trace variable unset for production and timings. The full significance interposer delegates initialize to the stock method and resets its retained per-instance state after every successful initialization.
